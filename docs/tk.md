# Working on Graphiga with TK

`./tk` is a small repository-local adapter for the workflow in `ticket`,
inspected from `../ticket` at
`194b71a`. It uses Graphiga's accepted predicate implementation and the committed
[ticket schema](../.tickets/schema.toml). It is not a drop-in replacement for
the original TK command or its YAML stores.

## Bootstrap

On x86-64 Linux, with Nix and Python 3 available:

```sh
./scripts/bootstrap-tk
./tk ready
./tk show bootstrap
```

Bootstrap builds revision `6c979bd973bdb54e382db82ccf424360ecd329fa` from a Git
archive using that revision's locked Nix environment and Cargo dependencies.
It installs the binary under ignored `.graphiga/bin/`. Ordinary ticket commands
use this executable, not the changing `target/` build. The bootstrap command is
idempotent. Changing the engine source does not replace it. macOS packaging and
validation are follow-up work.

The current development shell also provides Python:

```sh
nix develop --no-write-lock-file path:.
```

The wrapper finds `.tickets` relative to its own location, regardless of the
current directory. `TICKETS_DIR` selects a different existing Graphiga store;
relative paths are relative to the calling directory. To start an isolated store,
create an empty directory and copy `.tickets/schema.toml` into it. `GRAPHIGA_BIN`
selects an explicit engine executable, useful when testing a new build.

## Commands

```sh
./tk create "Implement the next change" -t task -p 2 \
  -d "Why this work matters" --design "Proposed approach" \
  --acceptance "What demonstrates completion" --tags cli,self-hosting
./tk ls --json
./tk show ID
./tk start ID
./tk dep ID PREREQUISITE
./tk ready
./tk blocked
./tk close PREREQUISITE
./tk undep ID PREREQUISITE
./tk link ID OTHER
./tk unlink ID OTHER
./tk status ID in_progress
./tk close ID
./tk reopen ID
./tk closed
```

Creation prints only the new `gr-xxxx` ID. Exact IDs win over substring matches;
otherwise a unique substring is accepted and ambiguous or absent matches fail.
`create` also accepts `--parent ID` and `--external-ref VALUE`. Use `--help` or
`create --help` for the complete argument list. Multiline section arguments work
as single quoted shell arguments. `ls` and `list` include all statuses. Views
support `--json`; their rows contain ID, type, and title, in ID order.

## Model and deliberate differences from TK

- Types: bug, feature, task, epic, chore. Default: task. All use Description,
  Design, and Acceptance Criteria headings; no TKO-specific types or sections.
- Statuses: open, in_progress, closed. Default: open. `blocked` is a query,
  never a stored status. Both open and in-progress tickets can be ready.
- Priority: 0 through 4, default 2, checked by the wrapper. Graphiga's integer
  schema does not itself impose a range. Views do not yet sort by priority or
  expose priority/status columns.
- Dependencies are directed. Only direct dependencies determine readiness;
  any dependency whose status is not closed blocks an active ticket. Parent is
  an independent directed reference. Closing does not enforce readiness.
- Links are reciprocal, with exactly two IDs per command. TK's multi-ID clique
  operation is not implemented. Graphiga's set operations are idempotent.
- Created timestamps are UTC strings generated by the wrapper. Tags are a
  comma-separated string set. Graphiga currently restricts string attributes
  (including tags and external references) to ASCII `-` through `~`, excluding
  spaces and commas. Titles and section bodies support ordinary prose.
- Assignees and the implicit `git user.name` default are deferred rather than
  silently changing names to satisfy the string restriction.
- Files use TOML frontmatter and filename identity, with no redundant ID field.
  Description is an H2 section; TK normally places it directly below the title.
  `show` returns the complete stored document, without TK's enriched summary.
- No YAML migration, notes append, editor command, arbitrary filters, plugins,
  dependency tree/cycle commands, store discovery, or mtime-based recent-closed
  view. `closed` returns all closed tickets in ID order. Edit prose with an
  ordinary editor between commands.

The wrapper never reads or writes ticket frontmatter. It obtains IDs from
Graphiga's JSON list and delegates graph operations and predicate evaluation.

## Working rules and verification

Use one writer at a time, including external editors. Graphiga v0 loads the
whole store and directly rewrites changed files; it has no lock, atomic file
replacement, or multi-file transaction. Keep work records in Git and review their
diffs. Write hardening is a follow-up, not a guarantee supplied by the wrapper.

The first ticket, [gr-bootstrap](../.tickets/gr-bootstrap.md), was written by
hand. Subsequent work tickets are created through `./tk` after its integration
checks pass. Ticket status records completion; Git history records file changes.
No command automatically commits or pushes.

Run the wrapper checks against a current engine build:

```sh
nix develop --no-write-lock-file path:. --command cargo build --locked
GRAPHIGA_BIN="$PWD/target/debug/graphiga" python3 tests/tk.py
```

Tests use temporary stores and exercise creation, graph queries, status changes,
body preservation, reciprocal links, partial IDs, and failures without writes.
They do not mutate the repository ticket store. CI runs these against the release
build as well as the engine's existing checks. When adopting a new bootstrap
revision, update the pin in `tk` and `scripts/bootstrap-tk` together and validate
the executable before using it for the real store.
